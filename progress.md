## Log

### 2026-08-20
- Design phase complete. `solution.md`, `Blueprints.md`, `ralphloop.md`, `prd.md`, `CLAUDE.md` written.
- `solution.md` revised after four independent technical reviews (Elementor domain, MCP protocol, security, delivery risk). Material corrections:
  - **V4 is GA and default for new installs since April 2026** — the create-path decision was inverted from "V3 containers only" to "the site's own generation".
  - **V4 detection must key on `widgetType`, not `elType`** — atomic content widgets are still `elType: widget`. Detecting on `elType` would silently corrupt nodes.
  - **V4 typed props nest** — flat `{$$type, value}` assumptions drop content.
  - **Draft-first on published pages means autosave revisions**, a second write path entirely.
  - **Capability-gated `tools/list` is not implementable** under MCP 2026-07-28; resolved by per-site connector URLs, which also binds sessions to one site and fixes the OAuth audience model.
  - **Prompt injection was unaddressed** and is the system's largest risk; §9.1 added.
  - **Nativeness demoted from a build gate to a warning** — as a gate it rewards one large HTML blob over several small ones.
- PRD written: 66 tasks across ten sections. Detail decreases with distance by design.

- Always check a verify command's **actual exit code**, not just its tail output — piping through `tail` has hidden a real failure more than once now (EMCP-006, and again mid-EMCP-009 before being caught). Use `; echo EXITCODE=$?` or otherwise avoid a pipe defeating the check.
- Killing a background test-server process in the `dev` container by `pkill -f`/pattern-matching `/proc/*/cmdline` is unreliable here (busybox `pkill`, and a naive pattern can match the killer's own command line). Find the exact PID first, then `kill -9` it, excluding `$$`.
- Three separate `node_modules` now exist (repo root, `server/`) plus `plugin/vendor` — normal for this multi-project layout, not a mistake, but worth knowing before assuming a single `npm install` at any one level covers everything.
- **V4 atomic widgets (`e-`-prefixed) have no introspectable settings schema yet** — `get_controls()` returns empty for them (they use `define_props_schema()` instead, confirmed against Elementor's source, EMCP-028, now in `CLAUDE.md`). `describe_widget` and `/registry/snapshot` both silently return an empty/near-empty control list for these widgets rather than erroring. Building a `define_props_schema()`-based reader is real, not-yet-scoped future work — no `prd.md` task currently covers it explicitly.
